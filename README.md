# 语文小题分分析工具

面向高中语文老师的单文件网页工具：读入监考系统导出的「小题分」表格，自动完成班级
大盘分析、小题得分率诊断、学生画像、跨考试历史跟踪，并支持导出 Excel 报表。历史
数据以一份「历史台账」Excel 文件为载体，跨考试累积。

**交付物**：`语文小题分分析工具.html`（单文件，约 1.2MB，双击即可在浏览器中打开
使用，断网可用，不依赖任何后端/服务器）。

本 README 面向**下一次维护/续写此项目的人（或 AI 编码助手）**，把最初的完整需求
规格、开发过程中与老师确认后追加/修改的规则、已验证过的坑与静态检查方法都记录下
来，减少重新对齐上下文的成本。

## 一、如何继续维护本项目（给 AI 助手 / 开发者的操作指引）

1. **先读完第二节「完整原始需求规格」和第三节「需求变更记录」**，这两节合并起来
   才是当前代码实现的真实依据（原始规格 + 老师追加的修改）。
2. 本项目**没有构建流程**，就是一个单 HTML 文件，直接用编辑器打开
   `语文小题分分析工具.html` 改。文件内部结构（按顺序）：
   - `<style>` 内是全部 CSS；
   - `<body>` 内是静态骨架 HTML（导航、筛选条、五个空的 `<section class="view">` 容器）；
   - 第一个 `<script>` 是 SheetJS（`xlsx.full.min.js` 源码，未压缩过的 UMD 版）；
   - 第二个 `<script>` 是 Chart.js（`chart.umd.js` 源码，UMD 版）；
   - 第三个 `<script>` 是全部业务代码，按顺序分为以下命名空间（对象）：
     `Utils` → `UI` → 常量（`FORMAT_VERSION`/`LEDGER_SHEETS`/`DEFAULT_TEMPLATE`/
     `defaultSettings`）→ `Store` → `AppState` → `Parser` → `Ledger` → `Stats` →
     `Charts` → `Wizard` → `Views`（及 `Views.Import`/`Views.Dashboard`/
     `Views.Portrait`/`Views.History`/`Views.Settings` 五个子对象）→ `Export` →
     `App`（初始化入口，`document.addEventListener('DOMContentLoaded', ()=>App.init())`）。
3. **改完代码后必须做语法静态检查**，因为这是单文件、无构建、无 TypeScript，
   括号写错一个就会导致整段脚本报错，从而白屏（第四节有详细教训记录和检查脚本）。
4. 本机环境没有 Node/npm，但有 Python（路径通常是
   `C:\Users\<user>\AppData\Local\Python\bin\python.exe`），可以用
   `pip install esprima` 装一个纯 Python 的 JS 语法解析器来做语法检查，
   具体脚本见第四节。
5. 如果需要真实浏览器渲染测试（不只是语法检查），可以用
   `pip install playwright` + `playwright install chromium` 跑无头浏览器测试，
   但注意国内网络环境下 `pip install` 有时会长时间无输出，**不要频繁轮询等待**，
   建议一次性 sleep 60~90 秒再检查结果，或者直接指定国内镜像源加速。

```
# 角色
你是一位精通前端（原生 HTML5 / CSS3 / Vanilla JS）与教育数据统计的开发者。
服务对象：一位高中语文老师。

# 任务
交付一个「语文小题分分析工具」：读入监考系统导出的小题分表格，自动完成班级大盘分析、

# 一、交付形态（硬性，不得偏离）

4. 单文件体积预期 1.2 MB 左右（SheetJS 约 950 KB、Chart.js 约 205 KB）。内嵌前必须校验
   库源码中不含 `</script`，否则会破坏 HTML 结构。
5. 目标浏览器：华为鸿蒙系统（HarmonyOS）自带浏览器优先，同时兼容 Edge / Chrome 的
   `file://` 直接打开方式。只使用标准 ES6、flex / grid、系统字体栈；
   不使用 File System Access API 作为必需依赖、不使用 ES Module、不使用
   import、不使用任何浏览器私有特性。
6. 本工具**不依赖任何后端、不依赖本地服务器**，必须能在 `file://` 协议下完整工作。

# 二、技术选型（已定，不要替换）

# 三、数据源规格：小题分表格（按真实样例核对过，必须严格支持）

表格为**三行表头**：

| 行 | 内容示例 |
| 第 1 行 | 合并标题，如「小题分(数学)」 |
| 第 2 行 | `学号` `考号` `姓名` `行政班级` `数学`(跨列) … `1卷`(跨列) … `2卷`(跨列) |
| 第 3 行 | `全卷` `1卷` `2卷`，以及每个小题：`单选13（4.0分）`、`单选13_答案（D）`、
  `1-6_1（4.0分）`、`1-6（24.0分）`、`17_1（6.0分）`、`17（14.0分）` |
| 第 4 行起 | 学生数据 |

必须实现的识别与清洗规则：

1. **表头定位**：向上扫描，找到包含 `学号` 的行作为第 2 行表头，其下一行作为第 3 行子表头。
   找不到 `学号` 时退化为含 `姓名` 的行，再找不到用首行。表头行号必须允许老师手动修正。
2. **字段列**：`学号`（唯一主键）、`考号`（读取但**不作主键、不参与统计**）、`姓名`、
   `行政班级`（分班统计用）、科目总分列（如 `全卷`）。
3. **满分解析**：从第 3 行列名的括号中读取，`（4.0分）` → 4.0。解析失败时允许老师逐题手动补填；
   满分为 0 时给出显式提示（否则得分率会算成无穷大）。
4. **答案列识别**：列名含 `_答案`、`答案`、`选项`（如 `单选13_答案（D）`）的一律剔除，
   不参与分析，界面上的勾选框置灰不可选。
5. **合计列识别（默认不计入分析，允许老师手动勾选纳入）**：
   - 卷面合计：列名为 `全卷`、`总分`、`1卷`、`2卷`、`合计` 等；
   - 大题合计（父题）：某列列名不带下划线，且它是另一批列名的下划线前缀。
     例：存在 `1-6_1` … `1-6_6` 时，`1-6（24.0分）` 是父题合计；存在 `17_1`、`17_2` 时，
     `17（14.0分）` 是父题合计。
6. **题号自动推断**（仅作初始建议，老师可改）：
   - `单选13` → 13；`多选6` → 6；`12` → 12
   - `17_1` → 17（下划线前无范围号，视为该题的子问）
   - `1-6_3` → 3（下划线前是范围 1-6，取「起始号 + 子问号 - 1」）
7. **容错**：分值可能是数字或字符串；缺考单元格留空；**学号必须按字符串处理**，
   防止 Excel 把它转成数字或科学计数法丢精度。姓名重名时一律以学号为准。
8. **粘贴导入**：除拖拽与点选外，必须支持在 Excel 里框选后 Ctrl+C、回到页面 Ctrl+V，
   按制表符切分后走同一套识别流程。

# 四、历史台账格式（本方案的核心，必须严格遵守）

## 4.1 定位
历史台账是一份由本工具生成、由老师保管的 **.xlsx** 文件，是跨考试历史数据的**唯一权威载体**。
老师在文件夹里长期保留这一个文件；每次分析完，工具导出一份更新后的台账，老师覆盖原文件。
**不为每次考试生成新文件**，避免文件越堆越多。

固定文件名：`语文小题分_历史台账.xlsx`

## 4.2 工作表结构

| 序号 | 工作表名 | 用途 | 是否被工具读取 |
| 1 | `台账说明` | 格式版本号、导出时间、考试次数、使用提示 | 读（仅取版本号） |
| 2 | `考试清单` | 每次考试一行 | **读** |
| 3 | `小题定义` | 每次考试的每道小题一行 | **读** |
| 4 | `学生得分` | 每个学生的每道小题一行（长表） | **读** |
| 5 | `班级得分率总表` | 人看的：行=标准题号，列=历次考试 | 忽略 |
| 6 | `历次考试概览` | 人看的：行=考试，列=平均分/最高/最低/及格率等 | 忽略 |

第 5、6 张是给老师看的只读视图；工具导出时重新生成，导入时**完全忽略**，
这样老师可以在台账里自己加分析表而不影响往返。

## 4.3 各表列定义（表头名必须与下表完全一致）

**`台账说明`**（前两列为键值对，固定行位置）：
`格式版本` = 1 ；`导出时间` ；`考试次数` ；`数据来源` = 语文小题分分析工具 ；
`提示` = 「请勿修改 考试清单 / 小题定义 / 学生得分 三张表的表头名称；其余工作表可自由增删」。

**`考试清单`**：
`考试ID` | `考试名称` | `考试日期` | `科目` | `学生人数` | `小题数` | `满分合计` |
`已对应题号数` | `备注` | `写入时间`

**`小题定义`**（每次考试 × 每道小题一行）：
`考试ID` | `小题序号` | `小题名称` | `原表列名` | `满分` | `标准卷题号` | `板块` |
`题型全称` | `是否计入分析`

- `小题序号` 为该小题在本次考试中的顺序（从 1 开始），是小题的稳定标识。

**`学生得分`**（长表，每个学生 × 每道小题一行）：
`考试ID` | `学号` | `姓名` | `班级` | `总分` | `小题序号` | `小题名称` | `满分` | `得分`

- `小题名称` 与 `满分` 冗余存储，目的是让老师能直接排序筛选，不必去关联另一张表。

## 4.4 台账读写硬性规则

1. **稳定 ID**：`考试ID` 由工具生成（如 `EX20260919-001`），一旦写入**永不改变**，
   重新导出时已有考试的 ID 必须原样保留，否则去重全部失效。
2. **按名读取，不按位置读**：导入时用工作表名定位工作表、用表头名定位列。
   允许老师调换列顺序、在末尾追加自己的备注列、增删视图工作表，工具都必须照常工作。
3. **文本格式保护**：写入时 `学号`、`考试ID`、`考试日期` 必须写为文本型单元格，
   避免 Excel 打开后被改成数字或日期序列值；班级名形如 `3班` 保持文本。
4. **单位与格式**：满分与得分写为数值；不要写百分比字符串，得分率一律由工具现算。
5. **唯一键**：考试的唯一键为 `考试ID`。若发现「考试名称 + 考试日期」相同但 ID 不同的记录，
   视为冲突，必须让老师选择处理方式，**不得静默丢弃任何一条数据**。
6. **版本兼容**：导入时先读 `格式版本`。版本高于工具支持的版本时，明确提示
   「台账由更新版本的工具导出，请升级工具」，并拒绝写入，避免降级破坏数据结构。

# 五、数据模型

一次考试：{ 考试ID, 名称, 日期, 备注, 小题列表, 学生列表, 写入时间 }
- 小题：{ 小题序号, 原表列名, 小题名称, 满分, 标准卷题号（可为空）, 是否计入分析 }
- 学生：{ 学号, 姓名, 班级, 总分, { 小题序号 → 得分 } }

另有一份可编辑的「完整卷模板」：{ 板块名, 题号, 题型, 满分 } 列表。

**默认预置语文·新课标全国卷模板（1~23 题，满分 150）**，可在设置页增删改：
| 板块 | 题号 | 满分 |
| 现代文（一） | 1~5 | 3/3/3/4/6 = 19 |
| 现代文（二） | 6~9 | 3/3/4/6 = 16 |
| 文言文 | 10~14 | 3/3/3/8/3 = 20 |
| 古诗鉴赏 | 15~16 | 3/6 = 9 |
| 名句默写 | 17 | 6 |
| 语言文字运用 | 18~22 | 3/4/4/4/5 = 20 |
| 写作 | 23 | 60 |

题号展示格式：「板块名 + 空格 + 原题号」，例如 `积累运用 1`、`现代文（一）3`。

（**注意**：见第三节「需求变更记录」，此默认模板在开发过程中被老师提供的
《完整考试题型.txt》替换为实际使用的语文标准卷结构，1~25 题，满分字段不强制。）

# 六、功能需求

## 1. 导入与台账合并
导入页顶部提供**一个接收多个文件的拖拽区**，自动判别文件类型：
- 含 `小题定义` / `学生得分` / `考试清单` 工作表的 → 历史台账
- 第 2 行含 `学号`、第 3 行是小题名的 → 小题分表格

必须支持以下三种用法：
- **只拖台账**：不新增考试，直接进入查看模式，可看大盘、画像、历史趋势。
- **只拖小题分**：走导入向导新增一次考试；若本地缓存里已有历史，把它们一起并入
  （并提醒老师确认台账是否已更新）。
- **台账 + 小题分一起拖**：一次完成合并，这是老师的常规用法。

导入向导 5 步（有进度条、可回退）：
1. 选文件（拖拽 / 点选 / Ctrl+V 粘贴）。
2. 填考试信息：**考试名称（必填）、考试日期（必填）**、备注（选填）。
3. 认字段与满分：表头行号可改；学号 / 姓名 / 班级 / 总分四个下拉；下方逐题可编辑
   满分、可勾选是否计入分析；提供「按原表自动填满分」「全部计入」「仅计入小题」
   三个快捷按钮。
4. 对题号（见第七节）。
5. 完成页：显示「本次新增 N 次考试 → 台账现共 M 次考试」，并提示导出更新台账；
   提供跳转到大盘 / 画像的按钮。

**合并与冲突处理（必须显式询问，不得静默处理）**：
- 新导入的考试若与台账中某次考试「名称 + 日期」相同，弹出选择：覆盖原记录 /
  保留为两次独立考试 / 跳过本次导入。
- 合并完成后显示：台账原有 M 次、本次新增 K 次、去重替换 S 次、最终共 N 次。
- 台账里数据损坏或列缺失时，指出具体是哪张表、哪一列，而不是笼统报错。

## 2. 班级大盘
- KPI：班级平均分、最高分（附姓名）、最低分（附姓名）、中位数、标准差、及格率、
  全卷平均得分率。
- **重灾区**：按得分率（班均得分 ÷ 该题满分）从低到高排序，自动标出前 3 题，
  卡片显示得分率、满分、班均得分、人均失分、零分人数、满分人数。
- 图表一：各小题得分率横向条形图，按得分率从低到高排列；低于 60% 红、60%~75% 橙、
  75% 以上绿。
- 图表二：总分分布直方图（满分 150 时每 10 分一档）。
- 「各班横向对比」表：多班时显示各班人数、平均分、最高、最低、标准差、及格率、
  各班最薄弱三题。
- 明细表：排序可切换（得分率低→高 / 高→低 / 失分最多优先 / 按题号），重灾区行底色标红。

## 3. 学生画像
- 下拉选学生（按分数排序，显示名次、姓名、班级、总分），并有「上一位 / 下一位」按钮。
- KPI：总分、班级排名（x / 总人数，同分并列要正确）、班级平均分、与班均差、薄弱小题数量。
- **薄弱题判定**：本人该题得分率 < 班级该题得分率 ×（1 − 阈值），阈值默认 15%，
  可在设置中调整。命中项单独成块展示，并在逐题表中**红字高亮**。
- 逐题对照表：满分、本人得分、本人得分率、班均得分率、差值、判定标签。
- 图表：本人得分率 vs 班级平均得分率的分组柱状图，薄弱题的本人柱标红。
- 若该生存在历史薄弱题，单独列出。
## 4. 历史跟踪（跨考试，数据来自台账）
- 选择学生 + 选择题号后：
  - 总分走势折线图：该生总分 vs 全班平均分，横轴为历次考试日期。
  - 指定题号的得分率走势折线图：该生 vs 全班，并画出达标参考线。
- **历史薄弱题判定（可配置）**：同一标准题号在该生参加过的考试中出现 ≥ N 次，
  且其中 ≥ N 次得分率低于设定阈值（默认 2/3），判为历史薄弱题。默认 N = 2。
  （**注意**：见第三节，此判定口径已被老师修改。）
- 矩阵表：行是各标准题号，列是历次考试，格子为得分率；低于阈值标红，缺考显示

# 七、题号映射（必须同时提供两种方式）
- **方式 A「自动套用完整卷映射」**：表格列出本次每一道小题，自动填入推测的标准
```

## 四、静态检查方法与开发教训（白屏排查记录）

### 4.1 曾经发生的真实故障：双击打开后"中间一片空白"

这是本项目开发过程中真实发生过的问题，记录下来是为了避免下次重复踩坑。

**现象**：老师双击 `语文小题分分析工具.html`，页面顶部导航能显示，但下面所有内容
区域一片空白。

**根本原因**：单文件、无构建流程，所有业务代码都写在一个大的 `<script>` 标签里。
在多次分段编辑（用编辑器工具追加代码块）过程中，有 3 处地方**漏写了对象/方法的
闭合符号**（缺 `},` 或 `};`），具体是：

1. `Views.History.renderCharts()` 方法体结束后缺少 `},`，导致下一个方法
   `renderWeakLists(className){` 被 JS 解析器当成了上一个方法内部的代码，
   触发 `Unexpected token {` 语法错误。
2. `Views.History` 对象结束后缺少 `};`，导致 `Views.Settings = {` 这行被当作
   `Views.History` 对象内部的非法语句，触发 `Unexpected identifier`。
3. `Views.Settings.render()` 方法内部两个 `addEventListener` 回调之间缺少 `},`，
   同类问题。

**为什么会导致整页空白，而不是"某个功能报错"**：因为 JS 引擎解析 `<script>`
标签内容时是**整体解析**的，只要有一处语法错误，浏览器会直接抛出
`SyntaxError` 并**完全不执行这个 script 标签里的任何代码**——包括最关键的
`document.addEventListener('DOMContentLoaded', ()=>App.init())`。`App.init()`
不执行，五个视图容器就永远是空的 `<section>`，导航栏本身是写在静态 HTML 里的，
所以还能显示，但下面所有内容全部消失。**这是单文件无构建项目最大的脆弱点**：
一个语法错误 = 整个应用失效，且浏览器不会有任何提示，只会安静地白屏。

**如何发现的**：本机没有 Node/npm，无法用浏览器直接调试报错堆栈，于是改用
Python 装了一个纯 Python 实现的 JS 语法解析器 `esprima`，把 `<script>` 里的
业务代码块单独提取出来跑 `esprima.parseScript(code)`，解析报错会精确报出
"第几行、第几个 token 不对"，据此逐个定位并修复了以上 3 处问题。

### 4.2 每次改完代码后必须跑的语法检查脚本

在没有 Node/浏览器控制台可用的环境下，用以下方法验证 JS 语法：

```powershell
# 1. 安装 esprima（纯 Python 实现的 JS 解析器，装一次即可）
# 国内网络如果卡住无输出，不要频繁轮询，一次性等 60~90 秒再查结果
& 'C:\Users\<user>\AppData\Local\Python\bin\python.exe' -m pip install esprima --disable-pip-version-check --timeout 20 --retries 1

# 2. 写一个提取脚本，把 html 里最后一个 <script>...</script>（业务代码块）
#    单独存成 .js 文件，再用 esprima 解析，报错会精确定位到行号
```

提取 + 解析的 Python 脚本核心逻辑（可临时写成 `_check.py` 跑完即删）：

```python
import re
import esprima

path = r"语文小题分分析工具.html"
with open(path, "r", encoding="utf-8") as f:
    content = f.read()

scripts = re.findall(r"<script>(.*?)</script>", content, re.S)
business_js = scripts[-1]   # 最后一个 <script> 是业务代码（前两个是 SheetJS/Chart.js）

try:
    esprima.parseScript(business_js)
    print("BUSINESS JS PARSE: OK")
except Exception as e:
    print("BUSINESS JS PARSE ERROR:", e)   # 会打印出 "Line NNNN: Unexpected token X"
```

拿到报错行号后，用 `Read` 工具查看该行附近上下文（通常是提取出的临时 .js 文件
行号，与原 html 文件行号有固定偏移，需要用 `Grep` 按内容定位回原文件），确认是
缺少闭合符号还是其他问题，再用 `Edit` 工具修复。

### 4.3 进一步的交叉验证（可选，用于排查"能解析但运行时报错"的问题）

语法能解析通过，不代表运行时不报错。还可以用正则脚本做以下几类交叉检查（这些
在最初开发时都跑过一遍，全部通过，供下次维护参考）：

1. **每个命名空间是否只定义一次**：用正则匹配所有 `const X = {` 和
   `Views.Y = {` 的行号，确认没有重名/重复定义。
2. **`document.getElementById('xxx')` 引用的 id，是否都能在某处的
   `id="xxx"` 定义里找到**（包括静态 HTML 骨架和 JS 里动态生成的 innerHTML
   字符串两处来源）。
3. **`querySelectorAll('.className')` 引用的 class，是否都能在某处的
   `class="...className..."` 定义里找到**。
4. **跨命名空间方法调用是否都能对应到定义**：比如 `Wizard.finishCurrentFile()`
   被调用了，就要确认 `const Wizard = {...}` 对象里确实定义了
   `finishCurrentFile(){...}` 这个方法。**这类检查曾经真的抓到过一个 bug**：
   `Parser.pasteTextToMatrix(text)` 被 `Views.Import` 调用，但 `Parser` 对象
   定义里漏写了这个方法（多次分段编辑时遗漏），导致粘贴导入功能会在运行时抛
   `TypeError: Parser.pasteTextToMatrix is not a function`。这个问题**语法
   检查查不出来**（因为语法完全合法，只是方法不存在），必须靠这类跨引用扫描
   才能发现。

如果需要真实浏览器渲染验证（截图、控制台报错、点击交互），本机装好 Python 后可以
尝试 `pip install playwright`，但同样要注意国内网络环境下装包可能长时间无输出，
**不要用"sleep 几秒 → 查看 → 再 sleep"的方式反复轮询**，容易卡在假死状态里；
一次性 sleep 足够长的时间（如 90 秒）再检查是否装好，效率更高。

### 4.4 第二次白屏（真实故障，已修复）：顶层引用未定义函数 → 整段脚本不执行

**现象**：双击打开后导航栏能显示，下方依然一片空白——和 4.1 的现象一样，但性质不同。

**根本原因**：常量区少了 `defaultSettings` 的定义，而 `const AppState = {…}` 是**顶层语句**，
里面直接调用了它（`settings: defaultSettings(),`，现第 509 行），于是脚本一执行就抛
`ReferenceError: defaultSettings is not defined`。这个 `<script>` 的**后续全部代码**
（包括末尾的 `document.addEventListener('DOMContentLoaded', …App.init())`）都不会执行，
五个视图容器永远是空的 `<section>`，因此只剩导航、内容全白。

**与 4.1 的关键区别（务必记住）**：4.1 是**语法错误**，4.2 的 `esprima` 能查出来；
这次是**运行时错误**，`esprima` 语法解析**完全通过**，语法检查查不出来，只有真的跑起来
才会暴露——而浏览器**不会在页面上给任何提示**，只会安静白屏。所以「语法通过」不等于
「不白屏」，改完代码后必须补一次运行时验证。

**如何发现**：用 Playwright 驱动本机已装的 Edge（**不需要下载 Chromium**）：

```python
b = pw.chromium.launch(executable_path=r"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe")
pg.on("pageerror", lambda e: print("PAGEERROR", e))   # 直接打印 JS 报错文本
pg.goto(pathlib.Path(html).as_uri())
```

监听 `pageerror` 即可拿到 `defaultSettings is not defined`，一步定位。

**修复**：在常量区（`DEFAULT_TEMPLATE` 之后、`Store` 之前）补回

```js
const defaultSettings = ()=> ({
  defaultWeakRate: 0.5, weakHitRatio: 0.5, portraitGapThreshold: 0.15,
  emphasisMetric: 'itemRate', weakThresholds: {}
});
```

（字段含义：全局默认薄弱阈值 / 命中比例 / 画像对比阈值 / 强调指标 / 按「板块|题型」的阈值覆盖。

**教训**：顶层执行的表达式（对象字面量里的函数调用、`JSON.parse`、`Object.assign` 等）
一旦引用了不存在的名字，整个 script 静默失效。除 4.2 的语法检查外，建议再跑一次
**「被调用但全文无定义」扫描**：正则收集所有 `名字(` 调用点，剔除对象字面量方法定义
（`名字(...){`）、`function 名字`、`const/let/var 名字`、箭头函数形参与 `resolve/reject`
之后再剩下的，就是真正缺失的标识符（本次扫描后只剩 `defaultSettings` 一个，直接锁定）。

### 4.5 选择题被误判为「父题合计」而被整个排除（同次修复，1 行）

**现象**：数学样例的「计入满分合计」只有 132，但学生全卷最高分是 146——**满分比得分还低**，
说明有题目被错误排除。

**根本原因**：`Parser.buildColumns()` 里父题合计的判定规则是「某列名不带下划线，且它是
另一批列名的下划线前缀」。实现时把**答案列**也算进了这「另一批列名」：`单选13（4.0分）`
因为存在兄弟列 `单选13_答案（D）` 而被判成父题合计（父题），连同它的得分一起被排除。

**修复**（`Parser.buildColumns()`，答案列不参与父题判定）：

```js
const baseArr = cols.filter(x=> !Parser.isAnswerColName(x.base)).map(x=>x.base);
```

**验证**（两份真实样例，`page.set_input_files` 走完整向导后读 `AppState`）：

| 样例 | 修复前 | 修复后 |
|---|---|---|
| `小题分(数学).xls` | 24 题计入 / 满分合计 132 | 28 题 / **150** ✅ 与验收第 3 条一致 |
| `小题分(生物).xls` | 18 题计入 / 满分合计 53 | 36 题 / **100** |

**教训**：答案列（`_答案` / `答案` / `选项`）与合计列是两套独立规则，任何「按兄弟列名
推断父题」的逻辑都必须先把答案列排除掉。

### 4.6 端到端回归脚本要点（已跑通，可复用）

用 Playwright + 本机 Edge，一份脚本就能覆盖导入、图表、导出、台账往返：

1. **投喂文件**：`page.set_input_files('#fileInput', [两份 xls])`。`#fileInput` 是
   `display:none` 的隐藏 input，Playwright 可以直接给它设置文件，不需要模拟拖拽。
2. **走完向导**：填 `#wizExamName` / `#wizExamDate` → 点 `#wizNext`（到第 3 步认字段与满分）
   → 再点 `#wizNext`（到第 4 步题号映射）→ 点 `#wizAutoBySeq` → 再点 `#wizNext`（提交）。
   **多文件时注意**：提交第 1 个文件后会自动跳到第 2 个文件的向导（回到第 2 步），
   不要一直等 `#wizGoDashboard`，否则会误判成"卡死"（本次排查就踩过这个坑）。
3. **读真实数值**：直接在页面里读 `AppState.examList()`——人数、小题数、计入满分合计、
   已映射题号数、平均分/最高分/最低分，比截图可靠得多（4.5 那个 bug 就是这样发现的）。
4. **图表与空态**：`#view-dashboard` / `#view-portrait` / `#view-history` 的 canvas 数量
   应分别为 2 / 1 / 3；`pageerror` 与 `console.error` 计数必须为 0；页面文本不含
   `NaN` / `Infinity`。
5. **台账往返（验收第 7 条）**：用 `browser.new_context()` 新开一个**独立上下文**
   （IndexedDB / localStorage 天然隔离，等价于"清空本机缓存"），只拖入上一步导出的台账，
   再比对 `AppState.examList()` 与首次导入是否逐项一致（本次结果：完全一致）。
6. **导出下载**：`with page.expect_download() as dl: page.click('#navExportLedger')`，
   再用 zipfile 读 `xl/workbook.xml` 校验 6 张工作表名是否齐全。
